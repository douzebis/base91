base91: 0.1.0 -> 0.3.2

Update `base91` (the basE91 binary-to-text encoder) from the C tool to the
Rust implementation that replaced it upstream.
Changelog: https://github.com/douzebis/base91/blob/v0.3.2/CHANGELOG.md

**For users, nothing to change.** The same three commands are installed
(`base91`, and `b91enc` / `b91dec`), reading and writing Joachim Henke's
basE91 format with the same options and defaults: `-d`, `-e`, `-m SIZE`,
`-o FILE`, `-v`, `-w COLS`.  Their output is byte-identical to the C
tool's: upstream CI compares the CLI with the original basE91 0.6.0
command-line tool on inputs of many sizes, and I checked every option
against the 0.1.0 package built from current nixpkgs.

Differences from the C 0.1.0 tool:

- New: `--simd`, a fixed-width variant of the format that SSE4.1, AVX2 and
  NEON encode and decode at several GiB/s (SIMD streams are recognized and
  decoded by plain `-d`); `--buffer` as the long form of `-m`.
- Errors: a usage error (unknown option, invalid value) exits with status
  2 instead of 1, with clap's messages; an unreadable input file is
  reported without its name.  `-m 0`, which made the C tool write
  nothing, now works (with the smallest buffer).
- `--version` and `--help` are worded differently, and the man page is
  generated from the CLI definition (`b91enc.1` and `b91dec.1` still point
  to it).
- New: bash, zsh and fish completions.

Packaging:

- `rustPlatform.buildRustPackage` instead of `make -C src`; the Cargo
  workspace is in `rust/` (`cargoRoot`), the CLI in `rust/base91-cli`
  (`buildAndTestSubdir`), and the CLI's tests run in the check phase.
- The man page and the completions are generated by the built binary
  (`base91 --man`, `base91 --completions SHELL`) and installed with
  `installManPage` / `installShellCompletion`; skipped when
  cross-compiling.
- `versionCheckHook`, `nix-update-script`, `meta.changelog`,
  `meta.mainProgram`, `longDescription`; `src` uses `tag`.

This PR previously proposed 0.2.2 (with a wrong "init" title, as `base91`
already existed); it is updated in place to 0.3.2.  0.2.2 had a soundness
bug in two library functions (`simd::*_unchecked`), fixed in 0.2.3; the
CLI never called them.

Upstream builds and tests this exact recipe (staged in the repository's
`nixpkgs/` directory) in its CI.  A Python binding,
`python3Packages.pybase91`, will follow in a separate PR once this one is
merged (it reuses this package's `src` and `cargoDeps`).
